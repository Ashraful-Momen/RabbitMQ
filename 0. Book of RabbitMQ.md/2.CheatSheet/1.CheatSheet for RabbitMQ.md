## 🗺️ পুরো সিস্টেমের ASCII Workflow (এক নজরে)

```
┌──────────────┐   "order.created"   ┌─────────────────┐
│   Producer   │────────────────────►│ order.exchange  │
│  (Order API) │                     │    (Direct)     │
└──────────────┘                     └────────┬────────┘
                                              │ binding: order.created
                                              ▼
                                     ┌─────────────────┐
                                     │  order.queue    │──┐ (ফেইল হলে)
                                     │  (Durable+DLX)  │  │ NACK(requeue=false)
                                     └────────┬────────┘  │
                                              │ deliver   │
                                              ▼           │
                                     ┌─────────────────┐  │
                                     │ SMS Consumer    │  │
                                     │                 │  │
                                     │ 1. SMS পাঠায়   │  │
                                     │ 2. সফল → ACK ✅ │  │
                                     │ 3. ফেইল →        │  │
                                     │    retry (max 3)│  │
                                     │ 4. তারপরও ফেইল ─│──┘
                                     └─────────────────┘  │ NACK
                                                          ▼
                                              ┌─────────────────┐
                                              │  dlx.exchange   │
                                              └────────┬────────┘
                                                       │ routing: order.failed
                                                       ▼
                                              ┌─────────────────┐
                                              │   dlq.order     │
                                              │ (ফেইলড মেসেজ      │
                                              │  এখানে জমা থাকে)    │
                                              └────────┬────────┘
                                                       ▼
                                              👀 Manual Review /
                                              🔁 Re-process / 🔔 Alert
```

**ফ্লো মনে রাখুন:** Producer → Exchange → Queue → Consumer → (সফল = **ACK** → মেসেজ ডিলিট) / (ব্যর্থ = retry → max retry পরে **NACK** → **DLX** → **DLQ**)

## 1. **RabbitMQ ইনস্টলেশন**

### ✅ **Docker (সবচেয়ে সহজ উপায়)**

```bash
# RabbitMQ + Management UI (port 15672)
docker run -d \
  --name rabbitmq \
  -p 5672:5672 \
  -p 15672:15672 \
  -e RABBITMQ_DEFAULT_USER=admin \
  -e RABBITMQ_DEFAULT_PASS=secret \
  rabbitmq:3-management
```

- **5672**: AMQP প্রোটোকলের জন্য (Producer/Consumer কানেকশন)
- **15672**: Web-based Management UI (http://localhost:15672)

> 💡 **ম্যানেজমেন্ট UI লগইন**:
> ইউজার: `admin`
> পাসওয়ার্ড: `secret`

```bash
# Python লাইব্রেরি
pip install pika
```

### ✅ **Ubuntu/Debian (APT দিয়ে)**

```bash
sudo apt update
sudo apt install rabbitmq-server -y
sudo systemctl enable rabbitmq-server
sudo systemctl start rabbitmq-server

# Management Plugin চালু করুন
```

## 2. **কনফিগারেশন ফাইল**

RabbitMQ-এর প্রধান কনফিগারেশন ফাইল:
`/etc/rabbitmq/rabbitmq.conf` (Linux)

```ini
# নেটওয়ার্ক কনফিগ

management.tcp.port = 15672

# ডিফল্ট vhost

# ডিস্ক ফ্রি লিমিট (স্পেস কম হলে মেসেজ গ্রহণ বন্ধ করবে)
```

## 3. **Exchange, Queue & Binding তৈরি (প্রোগ্রামেটিকভাবে)**

```
order.exchange ──[binding: routing_key="order.created"]──► order.queue
                                                              │ (DLX arguments)
dlx.exchange  ──[binding: routing_key="order.failed"]───► dlq.order
```

### ✅ **Python (Pika লাইব্রেরি ব্যবহার করে)**

```python
import pika

# কানেকশন
connection = pika.BlockingConnection(
    pika.ConnectionParameters(
        host='localhost',
        port=5672,
        virtual_host='/',
        credentials=pika.PlainCredentials('admin', 'secret')
    )
)
channel = connection.channel()

# Exchange তৈরি (Direct)
channel.exchange_declare(
    exchange='order.exchange',
    exchange_type='direct',
    durable=True  # সার্ভার রিস্টার্টে থাকবে
)

# Queue তৈরি + DLX সেট (ফেইলড মেসেজ কোথায় যাবে)
channel.queue_declare(
    queue='order.queue',
    durable=True,
    arguments={
        "x-dead-letter-exchange": "dlx.exchange",      # ← ফেইল হলে এই exchange-এ যাবে
        "x-dead-letter-routing-key": "order.failed"    # ← এই routing key দিয়ে
    }
)

# Binding (Exchange ↔ Queue সংযোগ)
channel.queue_bind(
    queue='order.queue',
    exchange='order.exchange',
    routing_key='order.created'
)

# DLX Exchange & DLQ (Dead Letter Queue) তৈরি
channel.exchange_declare(exchange='dlx.exchange', exchange_type='direct', durable=True)
channel.queue_declare(queue='dlq.order', durable=True)
channel.queue_bind(queue='dlq.order', exchange='dlx.exchange', routing_key='order.failed')

print("✅ Setup সম্পন্ন: exchange, queue, binding, DLX, DLQ")
connection.close()
```

> ✅ **`durable=True`** সেট করুন — নাহলে সার্ভার রিস্টার্টে সব ডেটা মুছে যাবে!

## 4. 📱 **সম্পূর্ণ প্রজেক্ট — কিভাবে SMS পাঠানো হয় (Step by Step)**

প্রশ্ন ছিল: *Exchange/Queue bind করলাম, কিন্তু SMS পাঠালো কিভাবে?* —
উত্তর: **RabbitMQ SMS পাঠায় না!** RabbitMQ শুধু মেসেজ ডেলিভার করে। **Consumer-এর ভেতরে আপনার নিজের কোড** (SMS gateway API কল) SMS পাঠায়।

```
RabbitMQ-এর কাজ: মেসেজ পৌঁছে দেওয়া (Waiter)
আপনার কোডের কাজ: মেসেজ পেয়ে SMS পাঠানো (Chef রান্না করা)
```

### প্রজেক্ট স্ট্রাকচার

```
sms-project/
├── config.py       # সব সেটিংস এক জায়গায়
├── setup.py        # Exchange/Queue/Binding/DLX তৈরি (১ বার চালান)
├── producer.py     # অর্ডার মেসেজ পাঠায়
└── consumer.py     # মেসেজ পেয়ে SMS পাঠায় + ACK + Retry
```

### 📄 ধাপ ১: `config.py`

```python
RABBITMQ_HOST = 'localhost'
RABBITMQ_PORT = 5672
RABBITMQ_USER = 'admin'
RABBITMQ_PASS = 'secret'

EXCHANGE     = 'order.exchange'
QUEUE        = 'order.queue'
ROUTING_KEY  = 'order.created'

DLX_EXCHANGE = 'dlx.exchange'
DLQ          = 'dlq.order'
DLQ_ROUTING  = 'order.failed'

MAX_RETRIES  = 3
```

### 📄 ধাপ ২: `setup.py` — একবার চালান

```python
import pika
from config import *

connection = pika.BlockingConnection(
    pika.ConnectionParameters(
        host=RABBITMQ_HOST, port=RABBITMQ_PORT,
        credentials=pika.PlainCredentials(RABBITMQ_USER, RABBITMQ_PASS)
    )
)
channel = connection.channel()

# 1. Main exchange
channel.exchange_declare(exchange=EXCHANGE, exchange_type='direct', durable=True)

# 2. Main queue (DLX argument সহ)
channel.queue_declare(
    queue=QUEUE, durable=True,
    arguments={
        "x-dead-letter-exchange": DLX_EXCHANGE,
        "x-dead-letter-routing-key": DLQ_ROUTING
    }
)

# 3. Binding
channel.queue_bind(queue=QUEUE, exchange=EXCHANGE, routing_key=ROUTING_KEY)

# 4. DLX + DLQ
channel.exchange_declare(exchange=DLX_EXCHANGE, exchange_type='direct', durable=True)
channel.queue_declare(queue=DLQ, durable=True)
channel.queue_bind(queue=DLQ, exchange=DLX_EXCHANGE, routing_key=DLQ_ROUTING)

connection.close()
print("✅ Setup সম্পন্ন!")
```

### 📄 ধাপ ৩: `producer.py` — অর্ডার মেসেজ পাঠায়

```python
import pika
import json
from config import *

connection = pika.BlockingConnection(
    pika.ConnectionParameters(
        host=RABBITMQ_HOST, port=RABBITMQ_PORT,
        credentials=pika.PlainCredentials(RABBITMQ_USER, RABBITMQ_PASS)
    )
)
channel = connection.channel()

order = {
    "order_id": "ORD-1001",
    "phone": "01712345678",
    "message": "আপনার অর্ডার ORD-1001 কনফার্ম হয়েছে। ধন্যবাদ!",
    "retry_count": 0          # ← retry ট্র্যাক করার জন্য (গুরুত্বপূর্ণ!)
}

channel.basic_publish(
    exchange=EXCHANGE,
    routing_key=ROUTING_KEY,
    body=json.dumps(order, ensure_ascii=False),
    properties=pika.BasicProperties(
        delivery_mode=2,              # persistent — রিস্টার্টেও থাকবে
        content_type='application/json'
    )
)

print(f"✅ অর্ডার মেসেজ পাঠানো হয়েছে: {order['order_id']}")
connection.close()
```

### 📄 ধাপ ৪: `consumer.py` — **এখানেই SMS পাঠানো হয় + ACK + Retry**

```python
import pika
import json
import time
import requests          # pip install requests
from config import *


def send_sms(phone, message):
    """
    👉 এটাই আসল SMS পাঠানোর জায়গা!
    RabbitMQ মেসেজ ডেলিভার করে — SMS পাঠায় SMS Gateway API।
    এখানে আপনার SMS provider-এর API কল করুন
    (যেমন: SSLWireless, AlphaSMS, Twilio, Bangladeshi gateway ইত্যাদি)
    """
    print(f"📱 SMS পাঠানো হচ্ছে → {phone}")
    print(f"   মেসেজ: {message}")

    # ---- বাস্তব উদাহরণ (আপনার gateway অনুযায়ী বদলান) ----
    # response = requests.post('https://sms-gateway.com/api/send', json={
    #     'api_key': 'YOUR_API_KEY',
    #     'to': phone,
    #     'message': message
    # })
    # if response.status_code != 200:
    #     raise Exception(f"SMS Gateway error: {response.status_code}")

    time.sleep(1)   # সিমুলেশন: SMS পাঠাতে ১ সেকেন্ড লাগলো

    # ফেইল টেস্ট করতে চাইলে নিচের লাইন আনকমেন্ট করুন:
    # raise Exception("SMS Gateway ডাউন!")


def callback(ch, method, properties, body):
    order = json.loads(body)
    retry_count = order.get('retry_count', 0)

    print("=" * 55)
    print(f"📦 মেসেজ পেলাম: {order['order_id']} (retry: {retry_count}/{MAX_RETRIES})")

    try:
        # ১. আসল কাজ: SMS পাঠানো
        send_sms(order['phone'], order['message'])

        # ২. ✅ সফল → ACK পাঠান → RabbitMQ মেসেজ ডিলিট করবে
        ch.basic_ack(delivery_tag=method.delivery_tag)
        print(f"✅ SMS সফল! ACK পাঠানো হয়েছে → মেসেজ কিউ থেকে ডিলিট\n")

    except Exception as e:
        print(f"❌ SMS ফেইল: {e}")

        if retry_count < MAX_RETRIES - 1:
            # ৩. 🔄 RETRY: কাউন্টার বাড়িয়ে নতুন মেসেজ হিসেবে আবার পাবলিশ
            order['retry_count'] = retry_count + 1
            ch.basic_publish(
                exchange=EXCHANGE,
                routing_key=ROUTING_KEY,
                body=json.dumps(order, ensure_ascii=False),
                properties=pika.BasicProperties(delivery_mode=2)
            )
            ch.basic_ack(delivery_tag=method.delivery_tag)  # পুরনো মেসেজ ACK
            print(f"🔄 Retry {retry_count + 1}/{MAX_RETRIES} হিসেবে আবার কিউতে পাঠানো হলো\n")
        else:
            # ৪. ☠️ MAX RETRY শেষ → NACK(requeue=False) → DLX → DLQ-তে যাবে
            ch.basic_nack(delivery_tag=method.delivery_tag, requeue=False)
            print(f"☠️ Max retry শেষ! মেসেজ Dead Letter Queue (dlq.order)-এ গেল\n")


def start_consumer():
    connection = pika.BlockingConnection(
        pika.ConnectionParameters(
            host=RABBITMQ_HOST, port=RABBITMQ_PORT,
            credentials=pika.PlainCredentials(RABBITMQ_USER, RABBITMQ_PASS)
        )
    )
    channel = connection.channel()

    # একসাথে ১টা মেসেজ (fair dispatch — ব্যস্ত consumer-কে স্কিপ করে)
    channel.basic_qos(prefetch_count=1)

    # auto_ack দিইনি → Manual ACK ব্যবহার করছি (নিরাপদ)
    channel.basic_consume(queue=QUEUE, on_message_callback=callback)

    print("⏳ SMS Consumer চলছে... (CTRL+C দিয়ে বন্ধ করুন)")
    channel.start_consuming()


if __name__ == '__main__':
    start_consumer()
```

## 5. ✅ **Acknowledgement (ACK/NACK) — কিভাবে ও কেন পাঠাবেন**

### ACK কী?

Consumer মেসেজ **সফলভাবে প্রসেস** শেষে RabbitMQ-কে বলে: *"কাজ শেষ, মেসেজ ডিলিট করো"* — এটাই ACK। ACK না পেলে RabbitMQ মেসেজ রেখে দেয়, Consumer মরে গেলে **অন্য Consumer-কে** দিয়ে দেয়।

```
            auto_ack=True (বিপজ্জনক!)                Manual ACK (নিরাপদ ✅)
            ─────────────────────────              ─────────────────────────
Queue ──► Consumer পেলো ──► সাথে সাথে ডিলিট       Queue ──► Consumer পেলো
            │ প্রসেসের মাঝে ক্র্যাশ!                        │ প্রসেস করলো
            ▼                                              ├── সফল → ACK → ডিলিট ✅
        মেসেজ হারিয়ে গেল ❌                               └── ক্র্যাশ → ACK নেই →
                                                              অন্য Consumer-কে আবার পাঠায় 🔄
```

### ACK পাঠানোর ৩টি রাস্তা (Python)

```python
# 1️⃣ সফল → ACK (মেসেজ ডিলিট হবে)
ch.basic_ack(delivery_tag=method.delivery_tag)

# 2️⃣ ফেইল, আবার চেষ্টা দরকার → NACK + requeue (কিউতে ফিরে যাবে)
ch.basic_nack(delivery_tag=method.delivery_tag, requeue=True)

# 3️⃣ ফেইল, আর চেষ্টা নয় → NACK, no requeue (DLX/DLQ-তে যাবে, না থাকলে ডিলিট)
ch.basic_nack(delivery_tag=method.delivery_tag, requeue=False)
```

### ACK-এর জীবনচক্র (ASCII)

```
RabbitMQ                    Consumer
   │                           │
   │ ──(1) মেসেজ ডেলিভার ────► │  মেসেজ "unacked" অবস্থায়
   │                           │
   │                           │ ──(2) প্রসেসিং (SMS পাঠানো)──
   │                           │
   │ ◄──(3) ACK ────────────── │  সফল!
   │                           │
   ▼
মেসেজ কিউ থেকে ডিলিট ✅

──── যদি (2)-তে Consumer মরে যায় ────

RabbitMQ ACK পায়নি ──► মেসেজ "ready" হয়ে আবার কিউতে
                     ──► অন্য Consumer পেলো ──► প্রসেস হলো ✅
                     (এজন্য Consumer idempotent বানান — ডুপ্লিকেট সহ্য করবে)
```

> ⚠️ **দুটি সোনালি রুল:**
>
> 1. `auto_ack=True` প্রোডাকশনে ব্যবহার করবেন না — ক্র্যাশে মেসেজ হারাবে।
> 2. `basic_ack` **সবসময় কাজ শেষে** পাঠান — আগে পাঠালে ক্র্যাশে মেসেজ হারাবে।

## 6. 🔄 **Retry Logic — ব্যর্থ মেসেজ আবার কিভাবে চেষ্টা হয়**

### কেন `requeue=True` দিয়ে retry করবেন না?

```
❌ খারাপ উপায় (infinite loop):
ফেইল → NACK(requeue=True) → কিউতে ফিরলো → আবার ফেইল → আবার ফিরলো → ♾️
(SMS gateway যদি ১ ঘণ্টা ডাউন থাকে, লুপ ১ ঘণ্টা ঘুরবে — CPU খাবে, লগ ভরবে)
```

### ✅ সঠিক উপায়: মেসেজের ভেতরে retry_count রাখুন

```
চেষ্টা ১: ফেইল → retry_count=1 করে আবার publish → পুরনোটা ACK
চেষ্টা ২: ফেইল → retry_count=2 করে আবার publish → পুরনোটা ACK
চেষ্টা ৩: ফেইল → MAX_RETRIES শেষ → NACK(requeue=False) → DLQ ☠️
```

### সম্পূর্ণ Retry কোড (consumer-এর callback অংশ)

```python
def callback(ch, method, properties, body):
    order = json.loads(body)
    retry_count = order.get('retry_count', 0)

    try:
        send_sms(order['phone'], order['message'])
        ch.basic_ack(delivery_tag=method.delivery_tag)          # ✅ সফল

    except Exception as e:
        if retry_count < MAX_RETRIES - 1:
            order['retry_count'] = retry_count + 1
            # নতুন কপি আবার পাবলিশ
            ch.basic_publish(
                exchange=EXCHANGE,
                routing_key=ROUTING_KEY,
                body=json.dumps(order, ensure_ascii=False),
                properties=pika.BasicProperties(delivery_mode=2)
            )
            ch.basic_ack(delivery_tag=method.delivery_tag)      # পুরনোটা ACK
            print(f"🔄 Retry {retry_count + 1}")
        else:
            ch.basic_nack(delivery_tag=method.delivery_tag, requeue=False)  # ☠️ DLQ
            print("☠️ DLQ-তে পাঠানো হলো")
```

### 💡 প্রোডাকশনে আরও ভালো: Delayed Retry (TTL + DLX প্যাটার্ন)

তৎক্ষণাৎ retry না করে ৩০ সেকেন্ড/১ মিনিট অপেক্ষা করতে চাইলে — **wait queue + TTL** ব্যবহার করুন:

```
ফেইল ──► retry.wait.queue (TTL=30s, কোনো consumer নেই)
            │ 30 সেকেন্ড পর TTL শেষ
            ▼ (DLX হিসেবে main exchange সেট)
      order.exchange ──► order.queue ──► আবার প্রসেস 🔄
```

```python
# Wait queue সেটআপ (setup.py-তে যোগ করুন)
channel.queue_declare(
    queue='retry.wait.queue', durable=True,
    arguments={
        "x-message-ttl": 30000,                    # ৩০ সেকেন্ড অপেক্ষা
        "x-dead-letter-exchange": EXCHANGE,        # TTL শেষে মূল exchange-এ ফিরবে
        "x-dead-letter-routing-key": ROUTING_KEY
    }
)

# ফেইল হলে সরাসরি republish না করে wait queue-তে পাঠান:
channel.basic_publish(exchange='', routing_key='retry.wait.queue',
                      body=json.dumps(order, ensure_ascii=False),
                      properties=pika.BasicProperties(delivery_mode=2))
```

> এতে SMS gateway ডাউন থাকলে প্রতি ৩০ সেকেন্ডে একবার করে চেষ্টা হবে — সিস্টেমে চাপ পড়বে না।

## 7. ☠️ **Dead Letter Exchange (DLX) — মরা মেসেজ কোথায় যায়**

### মেসেজ কখন "Dead" হয়?

```
মেসেজ Dead হয় যখন:
┌────────────────────────────────────────────────┐
│ 1. Consumer NACK/reject করে (requeue=False)   │
│ 2. মেসেজের TTL শেষ হয়ে যায়                   │
│ 3. Queue-র x-max-length পূর্ণ হয়ে যায়        │
└────────────────────────────────────────────────┘
              │
              ▼ (ডিলিট না হয়ে)
        DLX (dlx.exchange) ──► DLQ (dlq.order)-এ জমা থাকে
              │
              ▼
     👀 ম্যানুয়াল রিভিউ / 🔁 রি-প্রসেস / 🔔 অ্যালার্ট
```

### DLX সেটআপ (৩ ধাপ)

```python
# ধাপ ১: DLX exchange + DLQ queue তৈরি
channel.exchange_declare(exchange='dlx.exchange', exchange_type='direct', durable=True)
channel.queue_declare(queue='dlq.order', durable=True)
channel.queue_bind(queue='dlq.order', exchange='dlx.exchange', routing_key='order.failed')

# ধাপ ২: মূল queue-তে DLX arguments দিন
channel.queue_declare(
    queue='order.queue', durable=True,
    arguments={
        "x-dead-letter-exchange": "dlx.exchange",
        "x-dead-letter-routing-key": "order.failed"
    }
)

# ধাপ ৩: ফেইল হলে Consumer শুধু NACK(requeue=False) পাঠাবে — বাকিটা RabbitMQ নিজেই করবে
# ch.basic_nack(delivery_tag=method.delivery_tag, requeue=False)
```

### DLQ-র মেসেজ দেখা/রি-প্রসেস করা (dlq_consumer.py)

```python
import pika
import json
from config import *

def dlq_callback(ch, method, properties, body):
    order = json.loads(body)
    print("☠️ ফেইলড মেসেজ:", order['order_id'], "| retry:", order.get('retry_count'))

    # অপশন ১: শুধু লগ/অ্যালার্ট করুন, তারপর ACK
    # send_alert_to_admin(order)
    # ch.basic_ack(delivery_tag=method.delivery_tag)

    # অপশন ২: সমস্যা ঠিক হয়ে গেছে → retry_count রিসেট করে মূল কিউতে ফেরত পাঠান
    order['retry_count'] = 0
    ch.basic_publish(exchange=EXCHANGE, routing_key=ROUTING_KEY,
                     body=json.dumps(order, ensure_ascii=False),
                     properties=pika.BasicProperties(delivery_mode=2))
    ch.basic_ack(delivery_tag=method.delivery_tag)
    print("🔁 মূল কিউতে রি-প্রসেসের জন্য পাঠানো হলো")

connection = pika.BlockingConnection(pika.ConnectionParameters(
    host=RABBITMQ_HOST,
    credentials=pika.PlainCredentials(RABBITMQ_USER, RABBITMQ_PASS)))
channel = connection.channel()
channel.basic_qos(prefetch_count=1)
channel.basic_consume(queue=DLQ, on_message_callback=dlq_callback)
print("⏳ DLQ monitor চলছে...")
channel.start_consuming()
```

> ✅ **Production রুল:** প্রতিটা গুরুত্বপূর্ণ কিউতে DLX থাকবেই। DLQ-তে মেসেজ জমলে অ্যালার্ট যাবে — এমন মনিটরিং রাখুন।

## 8. **ক্লাস্টারিং ও হাই অ্যাভেইলেবিলিটি (HA)**

### ✅ **Mirrored Queues (HA Policy)**

```bash
# CLI দিয়ে HA Policy সেট
rabbitmqctl set_policy ha-all ".*" '{"ha-mode":"all"}'
```

অথবা Management UI → Admin → Policies → Add Policy:

- **Name**: `ha-policy`
- **Pattern**: `.*` (সব কিউ)
- **Definition**:
  ```json
  {
    "ha-mode": "all",
    "ha-sync-mode": "automatic"
  }
  ```

> 📌 **ক্লাস্টার সেটআপ**: কমপক্ষে 3 নোড (odd number) — নেটওয়ার্ক পার্টিশন হ্যান্ডলিংয়ের জন্য।
> 📌 নতুন সেটআপে Classic mirrored queue-এর বদলে **Quorum Queue** ব্যবহার করুন।
